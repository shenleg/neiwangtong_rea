# 1008 单聊输入通知静态契约

2026-10-28，按网页展示单聊对方输入状态的需求，对原版 Windows x86 样本定点静态核对。未运行原客户端、连接真实网络、读取聊天历史或凭据。本文不是原客户端真实发送/网页接收验收。

## 2. 精确格式

命令 `1008`，XML为：

```xml
<X_SEND_WRITTING docver="1"><TYPE>0</TYPE></X_SEND_WRITTING>
```

不是空包，`WRITTING`不能改成`WRITING`。没有消息编号、用户ID、时间或正文。

| 地址 | 静态事实 |
|---|---|
| `0x9e95a0` | 封包器vtable |
| `0x668b80` | pack入口 |
| `0x668c90` | unpack入口 |
| `0x9ec404` | `<X_SEND_WRITTING docver="%u"><TYPE>%u</TYPE></X_SEND_WRITTING>`模板 |
| `0x668c35` | `push 1`，提供docver |
| `0x668c57` | `push 0x3f0`，提供命令 |
| `0x60dfb0` | 正常输入通知生产者；`0x60dfdb xor ebx,ebx`，`0x60e08f mov [eax+4],ebx`，TYPE为0 |
| `0x668da0 / 0x668dbc` | 比较XML根并寻找TYPE；文本必须非空，之后转整数 |

原生UI回调不按TYPE分支，但当前只验证了正常生产者的`TYPE=0`。独立实现只接受此值；不把`TYPE=1`解释为停止，不接收XML自报的用户身份。

## 3. 身份关联与显示规则

- `0x668e48–0x668e55`取入站CMsg的`+0x10/+0x14`连接路由，经`0x664d00`向模块`+0x108`回调集合分发。
- `0x5bb853–0x5bb87a`注册`0x5be430`；后者按路由查连接，并在`0x5be487`要求连接状态`+0x8==2`。
- 上层`0x4d76f0`取连接资料`+0x20`的用户ID，经`0x420350`找已存在的聊天窗口，找到才调用`0x514d10`。通知本身不创建聊天消息或新窗口。
- `0x514d10`查控件`0x3eb`，通过虚表`+0x138`传0显示；随后`0x514d55 push 0x1388`、`0x514d5a push 2`设置timer 2，时长5000ms。
- 设置定时器经`0x53f460 → 0x52d4d0`，`0x52d500`先取消同ID旧timer，`0x52d58d`调用`SetTimer`导入。因此重复通知重新计时，不累计。
- `0x514d70`在timer 2到期时取消该timer，再找同一控件，通过虚表`+0x138`传4隐藏。
- 显示/隐藏含义另由导出`SetVisible@CSkinView`（VA `0x53d080`）核实：true路径传0，false路径传4。未恢复该控件完整本地化文案。

发送侧有`timer1 → 0x5bc370 → 0x60dfb0`，调度函数`0x514480`使用3000ms间隔。网页本次只展示接收状态，不发送1008，不将发送侧间隔当成显示超时。

## 4. 独立实现与验证范围

- `Client.receive`严格解析1008，要求当前对端已双向READY，把5秒有效期绑定当前连接自己的握手身份。
- 输入状态通过并发安全快照发布；Host只合并当前未停止、身份匹配的连接。断连后不再发布旧状态，新连接不继承旧Client的计时。
- Manager的`State.typing`只列出当前在线、尚未过期的身份，返回剩余毫秒数；不把姓名或用户ID写入输入通知运行事件，不把通知计为消息、未读或最近联系人。
- 浏览器只对相应单聊显示提示，按相对剩余时长在本地撤销；不依赖浏览器与服务端时钟一致。群聊不显示单聊输入提示。
- 合成测试覆盖格式、非法TYPE、未READY拒绝、身份绑定、重复计时、过期、快照复制及页面目标区分；独立loopback对端经默认Host和认证HTTP验证输入通知。未做真实客户端验收。
