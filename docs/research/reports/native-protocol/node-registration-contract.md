# 默认新节点的 304 字节初始化契约

本文记录后续静态调查恢复的新身份生成、默认发现包及连接角色规则。实现为 `identity.go`、`node.go`；它不是原客户端资料模板复制，也不保证对端已经接受新 Go 客户端。

## 1. 身份和会话必须分开

正常新 UserID 路径：`0x5f2760` 检查自己的 `acc`，缺失/无效进入 `0x5f29e0 → 0x592630 → CoCreateGuid`；`0x5f2a93–0x5f2aff` 按 GUID **内存字节 0..15**以 `%02x`生成32个小写字符，随后写入自己的 acc。不是 RFC UUID 字符串的标准字段打印顺序。

节点管理器还会另调用一次 GUID 生成，将该 GUID 的原始16字节复制到自己的65字节会话字段，其余49字节为零。**此字段不是 NUL 文本，也不是固定的字符串 `"1"`。**

独立实现使用操作系统随机源生成 v4 GUID 内存布局（版本位在字节7、variant在字节8），自己的 UserID 持久保存；每次管理器生命周期另生成新会话 GUID。不会读取或重置 Windows 原客户端的 acc，不沿用其用户标识或会话。

自己的状态文件损坏时明确失败，不按原厂可能采用的重置行为自动换身份。独占创建碰撞、随机失败与落盘失败都停止，不自动重试。

## 2. 默认 CorpNumber 为空的新节点布局

| 偏移 | 长度 | 已恢复规则 |
|---|---:|---|
| `0x00` | 4 | BE32 总长304 |
| `0x04` | 4 | BE32 type1/2/4，由调用点提供 |
| `0x08` | 4 | BE32 version1 |
| `0x0c` | 4 | 空 CorpNumber 正常插入的 FEATURE：BE32 `0x5fc1d8ec` |
| `0x10` | 4 | 本机 IPv4 网络字节 |
| `0x14` | 4 | 适配器广播地址；只是载荷字段，不要求实际向广播地址发送 |
| `0x18` | 2 | 实际 discovery UDP port，网络序 |
| `0x1a` | 2 | 实际 ENet 主端口，网络序 |
| `0x1c` | 2 | TCP 主端口；Go 仅实现 ENet 时明确不公布 TCP，值为0 |
| `0x1e` | 65 | 自己的 UserID UTF-8、NUL终止；正常新ID为32个小写hex |
| `0x5f` | 65 | 独立的新会话 GUID 原始16字节＋49个零 |
| `0xa0` | 4 | BE32 500；值已恢复，完整业务命名仍未知 |
| `0xa4` | 1 | 显式初始化零 |
| `0xa5` | 2 | 实际 reverse ENet 端口；未实现该 listener 时不公布，值为0 |
| `0xa7` | 2 | 此正常初始化路径 reverse TCP 为0 |
| `0xa9..0xcc` | 36 | FEATURE第2..10项；默认空配置没有其余项，明确为零 |
| `0xcd..0x12f` | 99 | 发送者显式 memset/DWORD 清零，非猜测补零 |

主要依据：`0x651af0` 初始化节点状态；`0x659050` 序列化；type1/type2/type4 调用点分别在 `0x657da0`、`0x658b90`、`0x651190`。正常原客户端可同时公告 TCP/ENet/reverse 端口；独立 Go 实验不虚报不存在的 listener。

实际接收入口允许主 ENet/TCP 至少一个非零，校验 FEATURE 有交集、UserID和会话字段均非全零。配置 CorpNumber 的完整编码规则并未作为新能力开放；不为加入未知组织猜测 FEATURE hash。

## 3. 角色不是按 IP 大小选

`0x6503c0` 比较完整65字节会话字段，按无符号字节词典序：

- 本机会话较大：连接对方正常主端口。
- 本机会话较小：等待对方连接正常主端口；原厂另可能尝试对方 reverse 端口。
- 相等：视为同一会话过滤，不能据此再生成一个 GUID 自动重试。

Go 的受限单对端实验不公布自己的 reverse listener，也不主动探测其他端点；按会话比较结果选择 `Connect` 或 `Accept`。这不等于已经实现原厂所有主/临时连接选择和去重规则。

## 4. 1000 中的必需资料不是可选开关

静态接收函数 `0x669cc0` 对部分字段有非空检查。已明确的一个真实失败来源是 `INFO/GROUP`：

- `0x66aeab` 将键地址 `0x9eaa38` 传给 XML 查找；该常量原始字节为 ASCII `GROUP`。
- `0x66aee6–0x66aee8`：元素不存在则转失败分支 `0x66c50c`。
- `0x66aefd–0x66af09`：内容长度为0同样转该失败分支。
- 解析失败路径 `0x66cabf` 明确清零返回值；`0x650f70` 对失败的 unpack 将消息改为内部下线事件3并重新排队。

`GROUP` 是联系人资料的分组名称，不是 QGROUP_ID，不触发加入原生群。本机实验采用明确的 `NWT-Go-Test` 标签，而不把它留空或复制对端目录名。

消息版本 `MSG` 同样不是聊天开关。已接受的原客户端资料为 `2:1`；声明控制消息兼容版本不等于已经实现聊天/文件分派。Go 实验只处理上线控制，其他业务命令只报告命令号，不伪造成功响应或保存其正文。
