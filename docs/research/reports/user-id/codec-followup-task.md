## 3. 必须补齐的证据

| 查询对象 | 必须回答的问题 |
|---|---|
| `0x6f9100` | 实际摘要算法和输入长度是什么？它在基础密钥、页密钥和 IV 中的用途分别是什么？ |
| `0x6f9170` | IV 如何从页号生成？中间整数运算、常量、字节序及最终摘要是否与固定参考实现一致？ |
| `0x6f9800 → 0x6f92c0 → 0x6f7540` 的调用点指令 | 页号、基础密钥、派生密钥、IV、读写模式和缓冲区长度分别通过哪些寄存器/栈位置传入？不能按存在隐藏参数的伪代码原型推断。 |
| 补齐表 `0xa8fa9c` 与 `0x6f9550 / 0x6f95a0` | 非敏感的算法补齐表是否与参考实现逐字节一致？口令的字节长度、截断、空口令和补齐规则是什么？不要读取或输出实际密钥。 |
| `0x6f97f0` 及安装 codec 的相关调用点 | 实际页大小来自哪里？读取第一页之前如何获得？是否有硬编码、受支持的大小限制或保留字节？ |
| 第一页和后续页处理 | 是否整页加密？SQLite 文件头如何恢复？页号从 0 还是 1 开始？是否有第一页特例、偏移或尾部保留区？ |

每个结论附静态地址、关键指令和原 Evidence ID。说明与参考源码的相同点及差异；若还有缺项，列出确切缺项，不用“看起来像 AES”替代兼容性结论。

## 4. 合成已知答案验证

静态参数完整后执行，不使用真实 `nr` 猜测模式、口令或页大小。

1. 使用人工固定测试口令和固定明文，按已确认的样本算法产生基础密钥、页密钥、IV 和整页密文。
2. 与固定提交的参考实现逐项比较。记录合成输入和预期字节，形成可重放向量；仅让两个公开库互通，不足以证明样本兼容。
3. 覆盖第一页、后续页、不同页号，以及证据确认支持的页大小；包含能够发现页号字节序错误的用例。
4. 用相同模式生成合成 `OrgStruct_*` 数据库，验证独立读取端只读打开、schema 读取、目标查询及写入拒绝。查询前后文件哈希一致。
5. 记录实现版本、构建选项、模式、页大小、测试命令和结果。这里只使用合成口令与合成联系人，不记录样本实际密钥。
