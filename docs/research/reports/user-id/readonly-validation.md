# 联系人提取工具：真实离线副本只读验证

本文记录独立授权后的Windows验证，不修改历史静态分析结论。工具用法见[contactid说明](../../../tools/contactid.md)，字段和codec依据分别见[联系人研究](user-id-report.md)与[codec报告](../nr-codec/nr-codec-report.md)。

## 1. 授权与执行范围

操作者明确允许从已验证客户端文件只读取得固定codec口令、在正常退出后准备私有副本并精确查询一个指定原始名称。操作者随后确认已通过客户端正常退出；执行前和执行过程中重新检查，同名进程数均为0。

- 客户端磁盘SHA-256与既有样本一致；只解析PE文件中已定位的静态常量，不执行EXE、不加载客户端DLL、不读取进程内存。
- 固定口令仅在内存使用，没有输出、保存为文件或写入Git。
- 仅访问当前实例的 `cache/db/nr`，不读取群成员、聊天、凭据文件或其他账户联系人行。
- 副本与检查结果位于仓库外私有目录，ACL仅授予当前用户与SYSTEM访问。源路径、真实身份表名、目标名称和完整哈希保存在私有记录中，本文不复制它们。
- 不重启或终止客户端、不修改发送配置、不创建AttemptID、不发送消息。

## 2. 文件与schema-only结果

| 检查 | 结果 |
|---|---|
| 当前实例的Green目录分支 | 已按实际EXE路径重新核实 |
| 正常退出后的进程检查 | 0个客户端进程 |
| 源文件及副本的WAL、SHM、journal | 均不存在，未执行恢复或删除 |
| 复制前后源文件与副本SHA-256 | 相同 |
| 解密头恢复的实际页大小 | 1024字节，未遍历参数 |
| 读写模式与reserved | 符合首版rollback及reserved=0要求 |
| `OrgStruct_*`身份表 | 仅一张；按当前唯一实例正常初始化、单身份表条件确认 |
| 列结构 | `PriKey / UpdateTime / OnlineTime / Type / Id / Data`，与静态契约一致 |
| schema-only读取联系人行 | 否 |

固定版SQLite3MC直接以只读方式读取加密副本，没有生成明文数据库。此结果将此前的“仅合成验证”扩展为当前实例真实离线副本的可读性验证，不代表所有实例、多身份或边文件都已验证。

## 3. 指定原始名称的精确匹配

schema-only成功后，在同一私有副本的唯一身份表中执行工具的严格schema/唯一索引检查，再读取 `Type=1` 的 `Id,Data` 进行原始 `U/Name` 精确匹配。

结果为 **`not_found`，匹配行数0，候选为空**。源库和副本校验通过，未跳过无效记录后声称唯一，也未扩大为模糊姓名、备注、IP或群成员查询。

此结果只说明指定原始名称未出现在本次联系人缓存的精确匹配结果中，不证明该用户不存在或没有内部ID。若输入是本机账户名称或UI备注，必须进一步明确其与本机身份或原始Name的对应，不能自动将表后缀当作该名称的发送目标。

## 4. 本机身份确认

操作者随后明确确认：所给名称属于当前这台客户端的本机登录身份，不是联系人列表中的另一位用户。因此联系人缓存的零匹配不用于判断本机身份。

联系人研究第4.2节已静态证明 `OrgStruct_<后缀>` 的后缀来自本机 `CUser +0x20`，与IPC用户字符串身份属于同一标识空间。基于已验证当前实例、唯一身份表、完整副本哈希及操作者对本机名称的明确确认，已从表后缀取得**本机原始身份ID**。原始值及确认依据仅保存在仓库外私有记录，不写入本文或Git；没有读取额外联系人行或再取一次实际口令。

这不是“通过联系人Name查到另一位用户”，也不能用本机ID代替其他同名联系人。

## 5. 保持不变的边界

已取得本机身份ID，但没有写入 `authorized_user_id`，没有发送或验证单聊送达。任何真实发送仍需具体目标、固定正文和次数的单独明确授权。
