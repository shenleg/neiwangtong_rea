# 固定 IPC 正文构造的可计算上界

本文补充默认字段、JSON 排版和 URL 分割的静态证据，推导发送端 `u(E(J(body)))` 的上界。复用提交 `a1cf368` 的[正文研究](../ipc-body/body-contract-report.md)，不修改其报告、发送代码、样本或历史发送记录。

## 1. 结论与适用条件

**在本样本 `0x4b8470 → 0x5f8380` 的固定构造路径中，可以采用：**

```text
n = 原始正文的 UTF-8 字节数，不含 NUL
S = 最终非空普通文本与链接片段的总数

u(E(J(body))) ≤ 7n + 450S + 1024
             ≤ 457n + 1024
```

据此选用 **Adapter 原始正文限额 512 字节**：

```text
457 × 512 + 1024 = 235008 ≤ 261950
剩余预算 = 26942 UTF-16 code units
```

这是由静态构造和计数得到的项目输入限额，不是厂商最大值。`u` 不计字符串终止 NUL，`E` 是既有六项外层转义，`J` 是该正文构造函数实际写出的完整 JSON。外层 XML/NUL 已由共同预算 `261950` 另行预留，不在本式中重复计算。

适用条件：

- 样本 SHA-256 `e7caef3fe744f9fe6ba90dd1d53b7e64241cb54020a8bf37be5e756e2fe881b1`，x86，ImageBase `0x400000`。
- 输入有效 UTF-8、无嵌入 NUL；长度检查按原始字节数，不按 rune 数。空正文仍由接口拒绝。
- 使用 `0x4b8470` 的默认元数据和片段构造；不把此式推广到 UI 富文本、图片、文件、自定义字体或外部提供的 JSON。
- 保留既有字面四字符 `\r\n` 替换语义；若接口承诺原文不变，仍应拒绝这一字面串。该替换不增加本式中的 `n`。

本轮只读取磁盘样本并运行独立的计数复核脚本，没有运行客户端、发送消息、读取运行内存或数据库，也没有修改发送实现。已知 UTF-8/NUL、两层转义、群/单聊 packer 和 CRT 超长行为不重新分析。

## 2. 默认字段全部有界

### 2.1 构造与字段来源

`0x5f6ce0` 在 `0x5f6d54` 调用默认初始化 `0x5f6d70`；后者的 `0x5f6d75 → 0x5f60c0` 清空版本、应用、标识三个宽字符串，并在 `0x5f60dd` 将 `+0x54` 类型设为 0。[C01–C03]

已有 `0x4b8470` 指令 B02 随后仅做：

- `0x4b84cb–0x4b8502`：将 `0x9d0b00` 的 `L"6.0"` 写入版本。
- `0x4b8526: CALL 0x592690`，`0x4b853b`：生成并写入内层标识。
- `0x4b855b–0x4b8592`：将 `0x9d0b08` 的 `L"shiyeline"` 写入应用。版本/应用原始字节见 C13。
- `0x4b85bc / 0x4b85c4`：只把字体大小标志 `+0x78` 设为 1、大小 `+0x7c` 设为 10。
- `0x4b85cf` 构造片段；`0x4b85de` 调 `0x5f8380`，其间没有其他元数据来源。

这里的内层 `id` 是正文 JSON 标识，不是外层 XML 的消息计数器。

| JSON 值 | 来源及本路径取值 | 值本身最大 units | JSON 引号及 E 之后最大 units |
|---|---|---:|---:|
| `ver` | 固定 `"6.0"` | 3 | 15 |
| `app` | 固定 `"shiyeline"` | 9 | 21 |
| `id` | `0x592690`，32 个小写十六进制字符；失败为空串 | 32 | 44 |
| `type` | `+0x54=0`，经 `0x593ce0` 的 `%u` 转成字符串 `"0"` | 1 | 13 |
| `ft.s` | 固定大小 10，以十进制字符串 `"10"` 输出 | 2 | 14 |
| `ft.n / ft.c / ft.b / ft.i / ft.u` | 相应标志关闭，不输出 | 0 | 0 |

最后一列包含一对字符串引号：每个引号经 E 变成 6 units，因此增加 12；字段名、冒号和排版在第 4 节另计。[C04–C08；既有 B08、B09]

### 2.2 标识的成功与失败分支

`0x592690`：

- `0x5926ab` 调用标识生成辅助；失败在 `0x5926b4` 压入 **地址** `0x99deec`，并非取该地址处的指针再跟随。
- `0x99deec` 原始四字节为 `00 00 00 00`，所以它是一个空宽字符串，不是 `"invalid"` 等失败文字。[C06]
- 成功路径 `0x5926d2–0x592733` 把 16 个值各自用 `MOVZX BYTE` 取为 `0..255`；`0x592741` 用 16 个 `%02x`、容量 `0x21` 输出。
- 格式串原始 UTF-16 字节为 `(25 00 30 00 32 00 78 00) × 16 + 00 00`；每个参数恰为两位十六进制，成功长度为 32，失败长度为 0。[C05、C07]

`0x593ce0` 的 `0x593cfc` 压入 `0x9e0e88`，原始字节 `25 00 75 00 00 00` 即 `L"%u"`，`0x593d13` 格式化 `+0x54`。本路径该值始终为 0，实际只有字符串 `"0"`。[C04、C08]

### 2.3 字体名等字段不会带入未知开销

`0x5f6d7f / 0x5f6d87 / 0x5f6d8d / 0x5f6d99 / 0x5f6da5 / 0x5f6db1` 关闭名称、大小、颜色、粗体、斜体、下划线标志；`0x4b8470` 仅重新启用大小并设为 10。[C02；既有 B02]

`0x5f8380` 的名称分支要求 `+0x58!=0` 且名称非空；颜色、粗体、斜体、下划线分别要求各自标志非零。条件在本路径均不成立；大小分支成立，`0x5f87e0` 调 `_itow_s`，`0x5f8822–0x5f8839` 写入 `ft.s`。**不需要读取或限制 UI 字体名，因为这条路径根本不输出它。**[既有 B08]

## 3. 片段集合及 S≤n 的证明

### 3.1 本路径只生成两种 JSON 元素

`0x5f61b0` 的 `0x5f6220 / 0x5f6222` 将片段类别、子类别清零。普通文本构造 `0x5f6260` 保留类别 0，子类别由其调用参数 0 指定；链接构造 `0x5f66c0` 的 `0x5f671f` 仅把类别改成 3。两者都在源串非空时复制完整文本。[C09；既有 B03、B05、B06]

`0x5fa0d0 → 0x5fa2d0 → 0x480500` 分配节点并复制临时片段；`0x480500` 从源复制类别、子类别及文本，不追加字段内容，也不读取任何外部字体配置。[C10–C12]

既有 B08 的 `0x5f8ae0–0x5f8c13` 与 `0x5f90fe–0x5f912d` 分别写出：

```json
{"txt":{"t":"normal","v":"正文片段"}}
{"lnk":{"v":"链接片段"}}
```

`"normal"` 的原始字节为 `6e 6f 72 6d 61 6c 00`。[C14] 两种元素都包含一个非空对象，且正文值只写入一次；本路径不能从用户正文生成图片、文件或任意 JSON 字段。

### 3.2 有效正则及重建结果的来源

以既有五个正则片段定义 `P / D / I / Q / H`：

```text
P = (?:(?:(mailto|ssh|ftp|https?)://)|^|\s+)
D = (?:[a-z0-9](?:[-a-z0-9]*[a-z0-9])?\.)+(?:com|net|edu|biz|gov|org|in(?:t|fo)|(?-i:[a-z][a-z]))
I = (?:(?:25[0-5]|2[0-4]\d|1\d{2}|\d{1,2})\.){3}(?:25[0-5]|2[0-4]\d|1\d{2}|\d{1,2})
Q = (?::(\d{1,5}))?
H = (/[^\s]*)?

R = P + "((?:" + D + "|" + I + "))" + Q + H
```

`0x4b424b / 0x4b4263 / 0x4b427a / 0x4b4292 / 0x4b42aa / 0x4b42c5 / 0x4b42de` 依次构造此式。`0x405080` 先复制左串，再在 `0x4050eb → 0x4052f0` 追加右侧字面量；`0x405140` 的 `0x40519a → 0x405420` 按相同方向追加右串，不插入新字符。[R01–R05]

关键连接常量原始字节：

| 地址 | UTF-16 字节，含 NUL | 值 |
|---|---|---|
| `0x9d0588` | `28 00 28 00 3f 00 3a 00 00 00` | `((?:` |
| `0x9b6b98` | `7c 00 00 00` | `|` |
| `0x9d0580` | `29 00 29 00 00 00` | `))` |
| `0x9d0594` | `3a 00 2f 00 2f 00 00 00` | `://` |
| `0x99dd74` | `3a 00 00 00` | `:` |

五个完整正则片段及上述常量的原始字节分别保存在 R06–R15 的查询文件，不从反编译预览猜括号。[R06–R15]

R 有四个捕获组，依次为 scheme、非空 host、port 数字和 path。内部结果数组还含两项辅助位置，所以正则组 1–4 对应数组索引 3–6。`0x8a3910` 在 `0x8a392c` 对正则组编号加 2，再在 `0x8a3948–0x8a3951` 读取该项的起止地址；`0x8aba80` 同样按捕获数加 2 初始化结果数组。[R16、R17]

`0x4b4480` 取数组 3/4/5/6 后重建：

```text
scheme + (scheme非空时的"://")
       + host + (port非空时的":") + port + path
```

- `0x4c56a0` 按捕获的原始 `[first,last)` 宽字符区间复制，不改大小写或编码；未参与匹配的可选组起止相等，得到空串。[R17、R18]
- `0x4b4774 / 0x4b4786 / 0x4b4798 / 0x4b47ad / 0x4b47bf / 0x4b47d1` 完成保序重建。
- host 正则不能匹配空串。scheme 非空时，原正则必有相邻 `://`；port 非空时必有相邻 `:`。因此重建值正是当前候选输入的一个**非空连续子串**，不是凭空补造的新 URL。[R01、R16–R18；既有 B04]

本证明不需要 URL 最短长度，也不依赖输入中的 URL 各不相同。

### 3.3 总量守恒与终止

令 `U` 为字面换行替换后正文的 UTF-16 units。有效 UTF-8 满足 `U≤n`；字面四字符替换为 CRLF 只减长。

对于当前串中出现 k 次、长度 d≥1 的识别结果：

- `0x4b4930` 的 `0x4b49c0–0x4b49eb` 加入命中前缀，再从工作串删除“前缀长度+d”；`0x4b4a0d` 继续查找，最后 `0x4b4a31–0x4b4a36` 加入剩余串。
- 各子串长度之和加 `k*d` 恰好等于当前串长度；重复 URL 删除的是不同出现位置。
- `0x4b4a70` 的 `0x4b4b3c` 递归处理子串，在相邻子串间通过 `0x4b4b73` 恰好补回 k 份链接片段。子串均严格短于父串。
- `0x4b4aa6–0x4b4aae`、`0x5f629d–0x5f62a0`、`0x5f66fb–0x5f66ff` 不为零长度字符串生成最终片段。

所以递归终止；对递归树归纳，所有最终文字值的 UTF-16 长度和为 U，每个最终片段至少 1 unit：

```text
S ≤ U ≤ n
```

这同时覆盖大量短 URL、重复相同 URL、URL 两侧空子串及不同 URL 触发的多层递归。中间复制不增加最终文字总量。[既有 B03–B06；`4b4930-instructions.json` 的 Evidence 见证据索引]

## 4. JSON 排版与固定开销

### 4.1 必要 writer 行为

- `0x715ab0` 在 `0x715b1a` 设置行宽 74，在 `0x715b24` 设置缩进步长 3；行宽不是空格填充长度。[W01]
- `0x716570` 的 `0x716598–0x7165c3` 只往当前缩进串追加 3 个 ASCII 空格；`0x7165f0` 的 `0x716605–0x71660f` 删除 3 个。[W02、W03]
- `0x716540` 先调 `0x7164c0`，再输出固定结构串。`0x7164c0` 在上一字符不是空格或 LF 时最多追加一个 LF，再追加当前缩进；上一字符为空格时直接返回。因此 `"key" : {` 的子对象开括号不会额外换行或再缩进。[W04、W05]
- 对非空 dt 数组，`0x716090 → 0x7162d0` 因元素是非空对象而选择多行分支；`0x71633f / 0x71634e / 0x71635d` 检查容器类型及非空状态。它不会把片段预写一遍后再复制进最终文本，单行数组缓存分支在此不执行。[W06–W09]
- 对象 writer 的既有 B11 在 `0x715f43 / 0x715f6e / 0x715f90 / 0x715f9f` 输出字段名、排版、`" : "` 和字段值；逗号只为 `2c 00`，不附空格。结尾 LF 是 `0a 00`。[W10–W12]
- JSON 值都由本路径构造：`0x70c189 / 0x70c343` 把 comments 指针 `+0xc` 置零；复制构造 `0x70c490` 先置零，`0x70c565` 仅在源 comments 非零时复制。没有 JSON 解析或设置注释操作。`0x71664d / 0x716723` 的 before/after-comment 辅助先检查该指针，因此不会输出注释内容。[W13–W19]

固定 JSON 最大深度是 root → dt array → 片段对象 → txt/lnk 对象；标量行最多缩进 12 空格，不随 S 增长。

### 4.2 每片段固定开销

下表先把正文值设为空串，仅计算其外层引号和固定结构；每片段额外计一个分隔逗号，连最后一片段也计入，避免依赖位置。

| 元素 | 去掉排版的固定 JSON，经 E 后 | 排版 ASCII 空格 | 排版 LF | 加末尾分隔逗号后的总数 |
|---|---:|---:|---:|---:|
| `{"txt":{"t":"normal","v":""}}` | 79 | 60 | 6 | `79+6×60+6+1=446` |
| `{"lnk":{"v":""}}` | 46 | 46 | 5 | `46+6×46+5+1=328` |

普通文本的缩进分别为 `6+9+12+12+9+6=54` 个空格，再加三处冒号各两个空格，总计 60。链接的缩进为 `6+9+12+9+6=42`，再加两处冒号共四个空格，总计 46。JSON 引号已经包含在 79/46 中：分别为 10/6 个引号，每个在 E 后占 6 units。输入值内部字符的开销在第 5 节另计，不漏计双引号。

因此可统一取 **每片段固定开销 450 units**，包含字段名、类别值、全部引号、括号、内部逗号、冒号、缩进、LF 和片段分隔逗号。[W01–W12；既有 B08、B09]

### 4.3 根对象及字体开销

把 dt 的元素暂时移除、内层 id 取最长 32 个十六进制字符，根对象结构为：

```json
{"app":"shiyeline","dt":[],"ft":{"s":"10"},"id":"ffffffffffffffffffffffffffffffff","type":"0","ver":"6.0"}
```

去掉排版后经 E 的固定长度为 226；本 writer 的根对象/ft/数组开闭排版最多有 44 个 ASCII 空格和 11 个 LF，合计：

```text
226 + 6×44 + 11 = 501
```

片段已经单独计入 dt 内的行与逗号，不在这里重复计。将全部根字段、字体大小及 JSON 尾部 LF 的固定开销向上取为 **1024 units**。[C01–C08、W01–W12]

`verify_bound.py` 只对这两个片段和根对象的固定形状计数，不重写 JSON 库，也不模拟完整最终消息。原始排版常量和字段常量在单次查询文件中保留。[W20、W21]

## 5. 正文字节数到最终转义长度

令 F(v) 为某个文字值经过已有 JSON 字符串转义、再经过 E 后的长度，不含外层一对字符串引号。复用既有 B12/B16/B18/B19：

| 输入字符或类别 | 每个输入字符的最终值长度 | 与 UTF-8 输入字节数的关系 |
|---|---:|---|
| 普通 ASCII | 1 | 1 倍 |
| 双引号 | 反斜杠 1 + `&quot;` 6 = 7 | 7 倍，最大项 |
| 反斜杠 | 2 | 2 倍 |
| `'`、ASCII 空格 | 6 | 6 倍 |
| `&` | 5 | 5 倍 |
| `<`、`>` | 4 | 4 倍 |
| BS/TAB/LF/FF/CR | 2 | 2 倍 |
| 其余 `U+0001..U+001F` | `\u00xx`，6 | 6 倍 |
| 基本汉字 | 1 UTF-16 unit / 3 UTF-8 字节 | 不超过 1 倍 |
| 补充平面 emoji | 2 UTF-16 units / 4 UTF-8 字节 | 不超过 1 倍 |
| `]]>` | `]]&gt;`，6 / 3 字节 | 2 倍 |

连续特殊字符、控制字符、中文和 emoji 均按字符相加；不会因相邻而产生更大的替换倍数。`&` 最先处理，不会再次转义后来生成的实体。字面四字符 `\r\n` 变为两个换行控制字符后，其值表示长度为 4，不增加该上界。

按 UTF-16 原文字单位也有 `F(v)≤7u(v)`。结合最终文字总量守恒：

```text
Σ F(v_i) ≤ 7 Σ u(v_i) = 7U ≤ 7n
```

若普通片段为 T、链接片段为 L，另可保留更细的已证明界：

```text
u(E(J)) ≤ 7n + 446T + 328L + 501
```

为使调用方只检查一个字节数，统一取整：

```text
u(E(J)) ≤ 7n + 450(T+L) + 1024
        ≤ 457n + 1024
```

**URL 很多时仍必须计入 `450S`；不能只写 `7n+B`。** S≤n 的证明使上式不依赖最短 URL、URL 分布或把正文误当作单片段。

## 6. Adapter 限额决定与验证

建议未来任意正文接口明确使用：

```text
MaxBodyUTF8Bytes = 512
len(bodyUTF8) ≤ 512
```

数学保证：在第 1 节指定构造路径中，`u(E(J))≤235008≤261950`。512 不是字符数，不对正文静默截断；过长直接返回输入错误。当前 Adapter 的固定正文接口和发送代码保持不变。

离线验证：

```bash
python3 -I docs/research/reports/ipc-body-bound/verify_bound.py
```

脚本复核固定计数和限额算术，并用普通文本、连续引号、连续特殊字符、全部非 NUL C0 控制字符、中文、emoji、重复短 URL 与字面 CRLF 做独立字符计数检查。有限样例不替代 S≤n 的静态归纳证明；脚本不调用客户端、不做长度扫描或试发。

这是完整序列化空间的上界，不声称已证明接收展示、送达、其他传输限制或厂商最大正文。对于本路径的版本、应用、内层标识、类型、字体和固定排版，没有剩余的无界字段。
