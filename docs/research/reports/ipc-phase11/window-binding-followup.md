## 1. 结论

**限定调试于 `2026-10-23T03:35:54.4232273Z` 确认：原目标 `0x18062C` 当时绑定 CMainDialog。对象虚表对应静态 `0x9b80dc`，对象内 HWND 为 `0x18062C`；只读取这两个 DWORD，共 8 字节。硬件断点已恢复，调试已解除，客户端仍存活，没有新增业务调用。**

此前元数据核验已确认三个 `SkinDialog` 的类窗口过程对应共享入口 `0x54fcd0`，但元数据本身不能证明对象身份。探针仍报告两个候选；本次没有改变 Resolve 规则、自动选择或关闭窗口。运行对象证据不作为已有发送任务的重发许可，也不能追溯证明首次调用曾进入 `0x449c60`。

首次实验的 Win32 调用确已完成；“已调用业务 IPC”只表示发送程序执行了带业务 `dwData` 的 `WM_COPYDATA`，不是特定 C++ 处理器或群发送函数的运行命中证明。首次投递结果保持 `unknown`，独立接收补充观察仍为“没有看到”。

## 3. 窗口过程查询与地址换算

本节元数据阶段在 64 位 Python 中通过 User32 查询，并通过 Toolhelp 枚举目标模块；此阶段没有调用 `ReadProcessMemory` 或附加调试器。后续经授权的 8 字节对象观察另见第 6 节。

| 查询 | 三个 SkinDialog 的实际结果 |
|---|---|
| `GetClassLongPtrW(GCLP_WNDPROC)` | 均为 `0x6CFCD0`，错误码 0 |
| `GetWindowLongPtrW(GWLP_WNDPROC)` | 均返回 0，错误码 5（`ERROR_ACCESS_DENIED`）；不能解释为无窗口过程 |
| `GetWindowLongPtrW(GWL_STYLE)` 对照 | 成功，分别与探针 style 一致 |

Toolhelp 返回 `ShiYeLine.exe` 的加载基址为 `0x580000`、映像大小为 8069120；上述类过程地址在该模块范围内。`SNAPMODULE | SNAPMODULE32` 的结果中存在两条相同名称、基址和大小的 EXE 记录，不能按记录条数解释为两个实例。最初要求恰好一条记录的检查因此停止；随后仅核对两条记录的相同地址范围，没有选择其他模块。

```text
RVA = 0x6CFCD0 - 0x580000 = 0x14FCD0
静态 VA = 0x400000 + 0x14FCD0 = 0x54FCD0
```

早期使用非指针版本 `GetWindowLongW / GetClassLongW` 查询过程字段均得到错误码 1413，不作为过程地址证据。使用与调用进程指针宽度匹配的 `*PtrW` 后，类过程读取成功，但窗口自身过程查询仍为错误码 5。没有提权、注入或重试其他访问身份，也没有依据类过程结果排除窗口被 subclass 的情况。

## 4. 与已有静态证据的比较

以下结论复用[第五阶段报告](../ipc-phase5/ipc-phase5-report.md)及其小型证据，不是新的运行命中记录：

1. `0x54fd20` 将 `SkinDialog` 类过程注册为 `0x54fcd0`；`CSkinDialog::Create @ 0x524890` 使用此通用类并将 HWND 写入 `this+0x240`。主窗口和隐藏 owner 共用该类，故类过程匹配不是主对象指纹。[N15、N16]
2. `0x43ea90` 构造主对象，设置虚表 `0x9b80dc`；`0x4029d0` 创建隐藏 owner 后以其创建主窗口。[N17、N18]
3. `0x54fcdc` 调用 `CSkinWndHost::FromHandle @ 0x535ab0`，`0x54fcf4` 将返回对象放入 ECX，`0x54fcf6` 调用共享 `WindowProc @ 0x535bc0`。后续 `OnMessage @ 0x535d50` 根据实际对象的虚表取得消息表。[N9、N22、N23]
4. 主虚表 `+0x288` 指向 getter `0x43d1f0`，主消息表初始化 `0x43d200` 将 `WM_COPYDATA (0x4a)` 绑定到 `0x449c60`。必须证明 HWND 查出的对象就是主对象，才能确定该绑定适用于这个窗口。[N19–N21]
5. 共享消息分发的正常 `LRESULT=1` 不提供对象身份或群送达证明。[N9、N22、N23、N25、N26]

现有证据没有给出可从窗口外部直接查询的 CMainDialog 专属属性判据，也没有恢复 `FromHandle` 的实现及配对登记规则。不能猜测映射必经 `GWLP_USERDATA` 或 `GetProp`。
