# 阶段十一续查：授权群在两张运行时群表中的状态

本文记录两张群表、管理器发送前置判断的静态复核，以及经操作者明确授权的一次群元数据快照。不包含真实群 ID、其他群 ID、群名、成员名单、聊天内容或凭据。

## 1. 结论

**`2026-10-23T05:01:19.3900114Z` 的一次暂停快照确认：唯一授权群 ID 同时存在于 UI 群表和原生群管理表；两处群对象内的 ID 都与本地配置原值精确相同。管理器 `+0x4` 非零，本机用户对象存在，本机用户 ID 长度非零。**

本次读取 342 字节，低于授权上限 8192 字节；两张表各只访问一个实际群节点。调试已解除，客户端仍存活，没有新增消息或业务调用，原始发送尝试记录逐字节未变。

这排除了**快照时**群未加载、UI/原生群表缺少授权 ID，以及上述管理器前置字段为空的情况。它不是首次调用时的状态记录，也没有观测正文构造、接收人集合或发送动作；首次投递结论仍为 `unknown`，禁止重发。

## 2. 本轮授权与边界

操作者通过选择题明确允许一次群元数据快照：

- 短暂附加并暂停当前授权实例，最多读取 8 KiB。
- 只沿授权 ID 的二叉树查找路径读取指针、群 ID、长度及必要节点标志，以及管理器前置字段。
- 查找途中遇到的其他群 ID 仅在内存中比较，不输出、不保存；不枚举全部群。
- 不读取群名、成员名单、聊天或凭据，不调用目标函数、不发送窗口或网络消息；完成后解除调试。

真实目标继续只读使用 `local/ipcexperiment/config.json`，未改变 ID、大小写、格式或授权范围。

## 3. 静态复核：两次查群，不是同一张表

样本 SHA-256 仍为 `e7caef3fe744f9fe6ba90dd1d53b7e64241cb54020a8bf37be5e756e2fe881b1`。优先复用 E25-G1/G2、E19、第五阶段和群 ID 报告；缺少原始指令的必要片段，用当前安装 Go 附带的 `golang.org/x/arch/x86/x86asm` 离线解码磁盘 EXE，不安装或下载依赖，不运行 EXE。

现成 `go tool objdump` 因样本没有 `runtime.pclntab` 而不能解码；初版辅助解码器遇到范围末端截断指令，随后给解码器预留 x86 最长指令的 15 字节余量，仅输出起始地址在指定范围内的完整指令。其结果也与已有 `0x54fcf4 / 0x54fcf6` 原始指令相符。所有补充结果是本地静态解码，不冒充新的 REA Evidence ID。

### 3.1 IPC 先查 UI 群表

- `0x4edeb2` 读取全局 `DAT_00b2899c`，作为 UI 群表单例。为空时的构造路径不在本次运行快照中执行。
- `0x4edfdc` 调用 `0x4db0a0` 查找，`0x4edffb–0x4edffd` 将结果节点与 end 节点比较；未找到走 `0x4ee02d` 的空对象路径。
- 找到时 `0x4ee012` 取节点 `+0x30` 的群对象，`0x4ee019` 调用 `0x4dba10` 复制；`0x4ee740` 仅在返回对象非空时追加结果。没有结果则 IPC 后续循环不调用原生群发送。[E25-G1/G2；第五阶段 H2/H4/H5]

### 3.2 原生发送再次使用管理器自己的群表

- `0x4b9caa` 读取 `DAT_00b292f0` 原生群管理器，`0x4b9cb5` 将群对象 `+0x8` 的 ID 字符串放入 ECX，`0x4b9cb9` 调用 `0x617600`。
- `0x61762d / 0x617631` 检查管理器 `+0x4`；`0x617633 / 0x617637` 检查群 ID 长度；`0x61763d / 0x617641` 检查构造后正文长度。任一为空都走 `0x61768c` 返回失败。
- `0x617643–0x61764c` 从管理器 `+0x10` 取本机用户对象，将其 `+0x20` ID 字符串地址作为参数调用 `0x61afe0`。
- `0x61b005 / 0x61b009` 以管理器 `+0x14` 为群表，再调用同一查找函数 `0x4db0a0`。`0x61b024–0x61b028` 的 end 比较失败时直接返回 0。

因此，磁盘 `qrp` 中有授权记录、UI 群表查找成功、原生管理器群表查找成功是三个不同事实，不能互相替代。本次快照分别验证了后两者。

### 3.3 本路径的资格函数有本机用户快速通过分支

`0x61afe0` 不能笼统称为完整群权限校验：

1. 它先要求群 ID 与传入用户 ID 非空，并在原生管理器群表中找到群。
2. `0x61b02e–0x61b03a` 将管理器的本机用户 `+0x20` 与传入 ID 交给字符串相等函数 `0x407110`。
3. `0x61b03f–0x61b04b` 在相等时直接返回 1；`0x407110–0x407144` 将字符串比较结果转换为相等布尔值。
4. 本发送调用在 `0x617643–0x61764c` 传入的正是同一管理器的本机用户 ID，因此在群已找到、ID 非空且状态未变的这条路径上，会走该快速通过分支，无须读取成员名单。

其他用户的分支还会访问另一张表及成员集合，不在本轮运行读取范围内。上述行为不是完整禁言、角色、网络状态或投递权限说明。管理器 `+0x4` 由初始化 `0x61607c–0x61608e` 赋值；本轮只记录非零，不将它命名为“已登录”或“网络已连通”。

| 字段 | 指令依据 |

| 容器 `+0x18` 为 head/end；head `+0x4` 为 root | `0x4dc400 / 0x4dc405`；`0x4edfe5` |
