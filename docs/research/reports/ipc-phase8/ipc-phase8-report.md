# 阶段八：业务 IPC 单次实验程序与本轮检查结果

本文说明受控实验的载荷、执行限制、验证结果及未完成项；不定义厂商标准协议。

## 1. 本轮结论

**程序与本地测试已完成，内网通动态发送未执行，当前不能进入正式 IPC Adapter 开发。**

原因：

1. 操作者选择“先完成程序与测试”，没有提供唯一授权 `group_id`，没有确认实际发送。命令程序中的 `authorizedGroupID` 保持空值，发送入口会直接拒绝。
2. 实际只读预检返回 `assessment=ambiguous candidates=2`，程序立即停止。未选择其中一个窗口、未关闭客户端对话框、未再次尝试定位或发送。串联命令的第二个架构预检没有执行。
3. 没有发送方或独立授权接收方的消息观察记录；内网通的 API 返回、`LRESULT` 和超时状态均为 **not_run**，消息结果为 **unknown**。

这里的“未执行”专指内网通业务 IPC。本地测试向测试子进程自己的隐藏窗口发送合成数据，不接触内网通窗口。

## 3. 样本身份检查

通过只读进程查询取得运行中客户端的映像路径，再读取该路径的文件并计算 SHA-256；没有读取进程内存、聊天数据库或凭据，没有运行新的客户端实例。

| 项目 | 本轮结果 |
|---|---|
| 同名进程数 | 1 |
| PID / session | 9656 / 2；仅为本次检查的生命周期标识 |
| 映像文件 | `ShiYeLine.exe`，完整安装路径仅留在本地，不作为代码默认值 |
| SHA-256 | `e7caef3fe744f9fe6ba90dd1d53b7e64241cb54020a8bf37be5e756e2fe881b1` |
| 与静态对象比较 | 完全一致；静态依据为 IPC 契约第 1 节、第五及第七阶段样本身份 |
| FileVersion / ProductVersion 查询 | 均未返回字符串，不使用它们声称版本已独立核实 |

这是运行进程所报告路径的**磁盘 EXE** 哈希核对，不是对进程映像内存逐字节比较。

程序实现的正式预检还会：

- 使用 `windowprobe.Resolve()`，要求唯一候选、已观察的隐藏 owner 关系、正常显示且非最小化。
- 读取对应 EXE 并与上述固定摘要比较；读取期间不允许其他程序写入或替换该文件。
- 只申请进程查询/同步权限，以创建 FILETIME 和存活检查拒绝 PID 复用。
- 只查询 Windows 用户 SID 和完整性 SID，比较同用户、同完整性级别，不保存 SID，不读取登录凭据。
- 比较 session 和 desktop；窗口枚举仍限定在当前 desktop。
- 哈希及身份查询后再次 Resolve；人工确认后及尝试记录落盘后也再次 Resolve，并要求与先前 Target 一致。

本轮实际程序预检在第一次 Resolve 即因歧义停止，**没有执行该次后续哈希、用户/完整性和 desktop 检查**。上表哈希来自此前独立的只读检查。测试中的同用户/完整性/desktop 查询仅对测试进程自身通过，不冒充对运行客户端的完整预检。

## 4. 实验载荷的完整字节说明

### 4.1 静态依据

- `0x449c60` 中 `0x44a119` 比较 `dwData=0x0fecf10f`；`0x44a124–0x44a1e3` 从三个已知起点读取字符串。[E22-I]
- `0x44cbd0` 两遍调用 `MultiByteToWideChar(65001,0,source,-1,...)`；源终止位置由 NUL 决定。[E22-U；第七阶段 P1]
- 接收文本分支及已复核的上层/基类路径没有以 `cbData` 限制三次源读取；基类本业务分支没有额外载荷读取。[第五阶段 N8、N9；第七阶段第 2–3 节]
- 三个宽字符串构造完毕后在 `0x44a20f` 进入 `0x4c41b0`，没有继续传递原始 `lpData/cbData`。[E22-I]

### 4.2 实验选择，而非恢复出的结构声明

本实验分配 **322 字节（`0x142`）** 的连续 Go 字节缓冲区，先初始化为零，然后写入三个字符串。只选这一种长度，不扫描长度，不追加大量尾部零，不试畸形数据。

令 `n` 为人工提供的唯一授权群 ID 的 ASCII 字节数；当前未提供真实 ID。

| 字节位置 | 实验内容 | NUL 位置 / 范围 |
|---|---|---|
| `0x000–0x007` | 8 字节 ASCII `group_id` | `0x008` 为 NUL |
| `0x009–0x063` | 实验空隙，初始化为零 | 不是已恢复的厂商字段或保留区声明 |
| `0x064–(0x064+n-1)` | 一个明确授权的原生群 ID，原样写入 | `0x064+n` 为 NUL；要求 `1 ≤ n ≤ 199` |
| `(0x065+n)–0x12b` | 如有剩余字节，保持零 | `n=199` 时没有此空隙 |
| `0x12c–0x140` | 21 字节 ASCII `NWT-GW-AUTH-TEST-0001` | `0x141` 为 NUL |
| `0x142` 起 | 不属于传送区域 | 不发送正文 NUL 之后的额外数据 |

包含关系：

```text
选择器 NUL：0x008 < 0x142
群 ID NUL：0x064 + n ≤ 0x12b < 0x142
正文 NUL：0x141 < 0x142
cbData = 实际缓冲区长度 = 0x142 = 322
```

`n≤199` 仅为本实验不覆盖正文起点的写入约束，**不是厂商群 ID 容量**。实验额外仅接受 ASCII 字母、数字、`_`、`-`，不 trim、转换大小写或解码，不接受名称、列表、通配符或多个群参数。这也是本地输入子集，不是恢复的厂商 ID 语法；真实授权 ID 不满足时停止，不自动改写。

`0x4c4377–0x4c4387` 把目标字符串交给一次 `0x4ee740`，`0x4ee740 → 0x4edfc0` 在可见包装中最多追加一个群对象；下游为 `0x4b9c80 → CQGroupMgr::SendMsg @ 0x617600`。[E23-I、E25-G1、E25-G2；第五阶段 `0x4db0a0` 证据 `ev_c7bbd87691a3a3eb233f4d32fa60313c0c750d8a34be3bf5bb0bd93d445a2b5b`] 不能据此宣称已经恢复所有 ID 语法。

### 4.3 COPYDATASTRUCT 和内存生命周期

首测只允许 Windows 386 构建：

| 结构偏移 | 字段 | 实验值 |
|---|---|---|
| `+0x0` | `dwData` | `0x0fecf10f` |
| `+0x4` | `cbData` | 322 |
| `+0x8` | `lpData` | 本进程连续实验缓冲区指针 |

结构总长 12 字节是 Win32 ABI，不是厂商载荷长度；amd64 原生结构布局为 24 字节，单独测试但禁止作为本次发送构建。缓冲区没有嵌套指针，调用期间不修改；`runtime.KeepAlive` 保持结构和缓冲区存活。Windows 系统消息负责跨进程复制，不采用自定义指针消息或异步发送。

## 5. 调用、人工确认和单次限制

代码入口：`cmd/ipcexperiment`；实验实现：`internal/ipcexperiment`。不修改客户端，不注入、不提权、不修改消息过滤，不提供 HTTP API。

默认只读检查：

```bash
go run ./cmd/ipcexperiment -exe 'C:\实际安装目录\ShiYeLine.exe'
```

只有后续操作者提供一个明确授权的原生群 ID、确认隔离环境及两个授权账号后，才能在本地绑定 `authorizedGroupID`，同步更新“本轮未授权”的测试断言并重新测试。**不要把真实群 ID 或私人尝试记录提交 Git。** 当前空值构建没有可用发送目标；没有 `-group-id`、`-text`、广播、批量、重试或选择器参数。

未来执行仍必须是 Windows 386，且必须显式请求 `-send`。程序会先预检，再显示实例 PID/HWND、群、固定文本、长度和私有记录路径；操作者必须逐字输入包含完整群 ID 与固定文本的 `SEND ONCE ...` 确认行。不得通过脚本预先填入确认来替代人工授权。

发送步骤：

1. 只读预检并等待逐字人工确认；不复用历史 PID/HWND。
2. 确认后重新 Resolve 和检查身份；歧义或身份变化立即终止。
3. 在 `%APPDATA%\neiwangtong-gateway\ipc-experiment\NWT-GW-AUTH-TEST-0001.jsonl` 用 `O_EXCL` 创建尝试记录并 `Sync`。路径固定，不可通过参数换一个记录来重新发送。
4. 再次定位同一实例；若失败，保留记录并停止，不自动恢复发送资格。
5. 创建**发送进程自身**的 message-only `STATIC` 窗口作为 `wParam`，不创建或修改客户端窗口。调用前再次核对目标 HWND 的 PID/TID。
6. 一次 `SendMessageTimeoutW`，超时参数 5000ms，标志 `SMTO_ABORTIFHUNG | SMTO_ERRORONEXIT`。不用 `SMTO_NOTIMEOUTIFNOTHUNG`，不广播，不持有业务/UI 锁。
7. 调用前同线程 `SetLastError(0)`，调用后保存 API 返回和立即捕获的错误码；保存独立 `LRESULT`、有效性、耗时及客户端存活检查。
8. 保存结果并落盘，然后询问客户端状态、发送方当前测试消息和独立接收方观察。崩溃、退出、多条或错误目标立即停止。输入中断或无证据时维持 `unknown`。

同一 Windows 用户配置目录中的记录已存在时拒绝再次执行，包括超时、写入失败、发送前最终检查失败和程序重启后；并发调用也只允许一个取得记录。不得删除记录重新试发。该控制不是客户端幂等协议，也不能撤销已发生的业务。

最终检查后窗口仍可能立即销毁或复用；该实验不宣称消除 Windows HWND 的时间竞争。

## 6. 返回值与人工观察的判定

| 记录 | 含义 |
|---|---|
| `invoked=false` | 发送封装在调用 Win32 之前失败；不能把零值结果当作一次有效 API 返回 |
| `api_return != 0` / `completed=true` | Win32 同步调用完成，不证明业务成功 |
| `lresult_valid=true` | 此时窗口结果可解释；`LRESULT=1` 仅与已知正常消息映射结果一致 |
| API 返回 0，错误码 1460 | `timeout=yes`；可能已执行，禁止重试 |
| API 返回 0，错误码 0 或其他值 | `timeout=not_reported`；不按耗时臆造具体超时原因 |
| `client_alive_after` | 调用返回后的只读进程存活结果；不证明业务没有异常 |
| `sender_observation` | 操作者对发送方当前授权群中这一条固定消息的观察 |
| `recipient_observation` / `recipient_observed` | 独立授权接收账号在正确群看见正确发送者的一条固定文本；不代表全部群成员收到 |
| `unknown` | 缺少独立证据；API 结果本身不能改变该状态 |

正常映射固定 `LRESULT=1` 的静态推导为 `OnMessage @ 0x535d50`、`WindowProc @ 0x535bc0`，见第五阶段 D 节 N9、N22、N23、N25、N26。群查找失败等正常返回也可能为 1。

API 失败、定位失败、输入或记录失败均返回命令错误，不自动重试。退出码 0 也不是送达凭证，应读取独立接收观察记录。

## 8. 是否进入正式 Adapter 开发

**本轮不进入。** 本地 fixture 证明调用代码可以跨进程传送这组字节并按期限返回；没有证明候选 HWND 接受内网通业务消息，也没有证明原生测试群实际收到。

后续仍需操作者提供唯一授权群、准备隔离账号及独立接收方、关闭附加对话框后重新预检，并在程序显示完整信息后人工确认一次发送。本轮没有授权这些后续操作。

若后续一次用例确认：正确样本与实例、无崩溃或异常发送、正确原生群、正确发送身份、发送方及独立接收方均恰好一条固定文本，则可以开始**仅针对该版本 `group_id` 文本路径**的 Adapter 设计和开发，保留 `unknown` 与禁止自动重试语义。该结果仍不等于恢复完整厂商协议，也不允许直接开放任意文本长度、特殊字符、私聊、多实例或生产部署。
