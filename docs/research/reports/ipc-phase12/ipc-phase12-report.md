## 2. 投递前置元数据：121 字节快照

先复用 E19 的 `0x61b350 / 0x61b150 / 0x6114f0` 伪代码，必要指令用安装 Go 自带的 x86 解码器离线核对磁盘样本，未安装或下载工具。

### 静态判断

- `0x61b350` 在管理器 `+0x34` 的群成员表按群 ID 查找。节点 `+0x40` 为该群成员集合的 head；`0x61b3de–0x61b409` 将 begin 与 end 比较，集合为空则不进入成员解析。
- 每个成员经 `0x61b150` 在管理器 `+0x94` 的路由表查询；`0x61b194–0x61b196` 未找到则返回零路由；`0x61b42e–0x61b434` 跳过零路由。非空成员集合不保证最终投递集合非空。
- `0x6176eb–0x6176ef` 在投递集合为空时直接走正常清理返回；`0x61774e` 仍设置返回 AL 为 1。
- `0x61151d–0x611524` 在传输对象 `+0x24` 为零时直接返回失败；群调用循环在 `0x617720` 调用后不汇总该结果。

独立私有 Windows 386 工具 `ipctrace0002.go` 只设置 UI 线程的硬件执行断点，不修改客户端代码，不读取正文、成员或路由内容，不启动发送器或代替人工输入。每次累计内存读取最多 8 KiB，默认不附加；启用后最多等待 9 分钟。

| 执行点 | 保存的非内容结果 |

| `0x44a119` | EAX 与业务常量一致，确认进入文本业务分支；随后该槽改观察 `0x44a255` 的业务处理结束 |
