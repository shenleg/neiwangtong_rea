# 最大纯中文正文真实验证异常与恢复记录

本文记录 2026-10-24 在用户明确授权后，群聊和私聊各发送一次 261003 个“中”造成的客户端异常及后续处理。**本次不是成功送达验证，静态序列化预算不能作为产品可用长度。** 不包含真实目标 ID、聊天正文、凭据或完整私有日志。

## 1. 范围与结论

此前[离线边界测试](../ipc-message-content/adapter-capacity-boundary-check.md)确认 Adapter 接受 261003 个常见汉字、拒绝再多一个，并由独立 fixture 完整传送对应载荷。用户起初选择只保留离线结果，随后另行明确授权扩大范围：向 `qun` 群和 `PVE-WIN11` 私聊各发送一次汉字“中”重复 261003 次，无换行、标识或其他字符，共两条，接受可能拒收、截断或卡顿，异常停止且不自动重试。

**两个同步调用均完成，但操作者随后分别报告客户端卡顿或退出，并报告超长消息持续尝试发送、界面卡死。** 没有确认任一目标完整收到 261003 字，两条任务继续为 `unknown`，没有追加 `recipient_observed`。

这说明 261003 字只是当前算法允许的序列化空间边界，**已经不适合当作正常客户端的可用发送长度**。现有 Adapter 尚未另加产品级长度限制；提交代码不意味着该异常已修复。实际独立接收成功范围仍是[500 汉字五段](custom-500-newlines-confirmation.md)，不是厂商最大正文。

## 3. 停止与恢复

- 收到异常报告后停止全部发送，没有扫描其他长度、重放任务或自行重启客户端。
- `2026-10-24T10:17:33.5518807Z` 只读检查显示原发送端 PID 2652 已不存在。先前 `ClientAliveAfter=true` 只说明同步调用刚返回时存活，不能证明后续稳定。
- 随后发现新客户端进程 PID 7496，路径为原已核实的安装路径；用户授权结束该进程并只读定位队列后，正常执行进程终止，随后确认客户端进程数为 0。
- 只查看数据根目录的文件名、大小、修改时间，并检索既有静态证据。**没有定位到已确认的持久化重发队列、表或精确删除对象，未读取真实数据库正文、聊天、凭据或进程内存，未修改、删除或改名任何客户端数据。** `cache/db/ol` 的用途未确认，未把它作为清理目标。
- 用户随后明确表示自行重新安装已解决问题。本会话没有执行卸载或重装；不据此推定具体是哪种队列、记录或显示处理引发异常。

用户之后提出测试 2000 汉字，已确认计划正文和两个目标，但在发送前转为提交、合并和推送任务。该轮只读看到重装后单一客户端进程，**2000 字测试未执行，没有创建该轮发送记录**。
