# 五百汉字加换行的群聊、私聊真实验证

本文记录 2026-10-24 在用户明确授权后，向原群和原私聊接收者各发送一次 500 汉字五段正文的结果。不包含真实目标 ID、聊天历史、凭据或原始私有日志。

## 1. 结论

**`qun` 群和 `PVE-WIN11` 私聊均已独立确认本轮恰好新增一条消息，发送者正确、500 个汉字完整、四个显式换行正确。** 两次确认随后分别通过 `RecordObservation` 追加 `RecipientObservation / one`，均返回 `recipient_observed`。

- 群聊输入使用字面 `\n`，转换为 4 个实际 LF。
- 私聊输入使用字面 `\r\n`，转换为 4 组实际 CRLF。
- 每条正文均是 5 段，每段恰好 100 个汉字；换行不计入 500 个汉字，没有另外添加标点或英文标识。
- 接收窗口较窄时可自动折行；独立观察核对的是四个显式换行分隔出的五段及正文完整性，而非强制要求屏幕恰好显示五个视觉行。
- 两个目标各实际调用一次，共两次，不重试；接收观察和只读日志核对均不发消息。

本次把[此前短消息换行验证](custom-message-newlines-confirmation.md)扩展到上述 500 汉字样本，不证明更长正文、其他内容的全部边界或厂商最大长度。

## 2. 本次完整正文的确定方式

用户确认发送之前，已展示完整五行正文并离线核对字数。全文由以下 **20 个汉字**构成的片段重复生成：

```text
这是用于验证中文长消息换行显示效果的测试
```

每段连续重复该片段 5 次，得到 100 个汉字；五段内容相同，段间插入换行，共 500 个汉字和四次换行。这一规则唯一确定完整正文，没有随机、隐藏或事后添加的内容。

操作者明确选择向 `qun` 群和 `PVE-WIN11` 各发送一次上述完整正文，共两条，失败或超时不重试。该授权不重放之前的短消息任务。

## 3. 目标和执行控制

- 只读复用此前固定正文成功记录中的群/用户原始 ID，核对唯一预约、实际调用和独立接收确认；群 ID 与现有私有配置一致。
- 私聊原始 ID 还与操作者此前确认的 `PVE-WIN11` 完整常量严格比较，未按名称重新解析、猜 ID 或读取联系人库。
- Windows 386 私有程序直接使用当前正式 `internal/ipc`，`NewAdapter / Preflight` 核对唯一客户端 PID 2652、HWND `0x3030A`，样本哈希及同用户/完整性、session、desktop 检查通过。
- 群聊和私聊各使用新的独占执行记录，写入并 Sync 后才调用；记录已占用即停止，不改名、删除或换标识重试。
- 没有运行原短消息程序的发送模式，没有读取聊天、运行内存或凭据，没有改客户端或真实配置。
